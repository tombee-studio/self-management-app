# 外部決済イベント連携 要求

- **バージョン**: v0.4.0
- **ステータス**: done
- **更新日**: 2026-11-01（JST）

## 背景・目的

Apple Pay等の決済データを取り込み、重複・記録漏れを減らす。

## スコープ・責務

Apple Payアダプタ、共通イベント正規化、IDまたは近接条件での重複排除、店舗名からのカテゴリ推定、ディープリンク取り込み、ショートカットからのAPI登録、結果確認。Google Pay等の新アダプタは対象外。

対象者は自分の家計を管理する個人。全9機能を対象とするownerの2026-11-01の指示に従う。他機能との境界は[REQ一覧](../REQ.md)で管理する。

## ユースケース

連携ガイドを見てショートカットを設定 → 決済イベントを送信 → 正規化して保存 → 通知または次回起動で確認・修正。

## 受け入れ基準

<a id="ac-01"></a>
- **AC-01**: 有効な決済データを共通形式へ変換し、日本円の整数支出として保存する。

<a id="ac-02"></a>
- **AC-02**: 同一外部取引IDの再送を登録せず、IDなしでは記録元・金額・正規化店舗名が一致し決済日時差が3分以内の明細を重複とする。

<a id="ac-03"></a>
- **AC-03**: ショートカットAPIによるバックグラウンド記録を次回API取得後に一覧へ反映する。

<a id="ac-04"></a>
- **AC-04**: 金額・通貨・日時が不正なイベントは保存せず、失敗を呼び出し元へ返す。金額制約は手動支出と同じ。

<a id="ac-05"></a>
- **AC-05**: 店舗名のキーワードでカテゴリを推定し、一致しなければ未分類にする。削除済みカテゴリを参照しない。

<a id="ac-06"></a>
- **AC-06**: ロック中の操作はアプリ前面起動を必要としないAPI経路を使い、通信失敗はショートカット側に通知する。

<a id="ac-07"></a>
- **AC-07**: 取り込み成功・重複・失敗を区別して表示する。アプリ経由の成功時は許可があればローカル通知を発行し、通知タップで該当明細の編集を開く。背景API経路の通知はショートカット側とする。
