9機能を、責務ごとの境界へ

業務集約はLambda側に配置。日次・履歴は支出台帳のReadModelです。

SERVER / CORE

ExpenseLedger

Expense集約と読み取りモデル。記録・編集・削除・復元を一貫して扱います。

  • 手動支出MAN-C01〜05 · Record / Modify / Delete / Restore / CloseDraft
  • 日次ダッシュボードDASH-C01〜02 · 日次サマリー / 再取得
  • 履歴HIST-C01〜03 · 検索 / 合計 / 日付選択

CloseDraftと日付選択のUI状態はアプリ側に保持します。

SERVER / SUPPORT

CategoryCatalog / Budgeting

分類と予算はそれぞれ独立した集約です。

  • カテゴリCAT-C01〜04 · Upsert / Reorder / Retire / EnsureDefaults
  • 予算BUD-C01〜03 · Configure / Calculate / EvaluateThresholds

カテゴリ廃止先の恒久対応と予算配分削除を同一取引で確定し、全ReadModelで未分類へ解決します。

SERVER / INTEGRATION

PaymentIntegration

外部入力を正規化する腐敗防止層（ACL）。台帳が所有するPortへ保存を委譲します。

  • 決済連携PAY-C01〜04 · Normalize / Ingest / Background API / PresentResult

外部IDまたは記録元・金額・店舗・180秒の条件で重複判定。結果通知はアプリまたはShortcut側です。

DEVICE / APPLICATION

CloudAccess

HTTP要求、画面再取得、接続設定、結果不明と再試行を調整する技術的能力。

  • クラウドデータアクセスSYN-C06 / C08〜10 · Cost / Refresh / Send / Connection

費用構成検査はデプロイ構成側の検査です。旧Replication・Push/Pullは廃止しています。

DEVICE / PURE POLICY

PresentationPolicy

レイアウトとナビゲーション、メモリ内の入力状態を扱います。業務集約は所有しません。

  • 共通UIUI-C01〜03 · ResolveLayout / ReflowDraft / Navigation

幅600 / 840でレイアウトを切り替え、リサイズ時もドラフトを維持します。

BUILD / ASSETS

BrandAssets

既存マスターから配布アイコンを生成・検査するビルド時の技術的能力。

  • アイコンICON-C01〜03 · Validate / Generate / Installed Review

業務データやAWS APIへ依存しません。

依存方向：API Adapter → Application → Domain / Domain所有Port。InfrastructureがPortを実装します。DomainはAWS SDK・Flutter・HTTP具象へ依存しません。

公開HTTP API

  • POST /commands — 登録・更新・削除・復元・設定
  • POST /queries — 日次・履歴・予算・各Get操作
  • GET / POST /payment — Shortcut・アプリからの決済取込
  • GET /health — API版と稼働確認

版と運用上の前提

HTTP schemaVersion = 3 / 操作契約 = 2.0.0 / 内部イベントschemaVersion = 2。

固定OwnerIdは識別子です。現行設計にはAPIキー・Authorizerを追加していません。単一所有者向けで、認証方式の追加は今回の設計変更の対象外です。

月500円は運用目標。取得量・保存量・実際の費用を別途検証します。

Queryはowner世代を取得の前後で強整合読取し、一致した場合だけ応答します。世代が変わったカーソルは409で失効し、先頭から取得し直します。
