# ADR-0001: 既存9機能を対象として文書を整合させる

- **バージョン**: v0.1.0
- **ステータス**: done
- **日付**: 2026-11-01（JST）
- **決定状態**: accepted
- **決定者**: owner（本セッションの回答）

## 背景・課題・制約

Issue #1は基本支出管理を起点としていたが、既存資料は予算・カテゴリ・決済連携・クラウド同期・共通UI・アイコンまで含んでいた。最初の文書整理では対象範囲を保留し、矛盾する旧仕様と詳細設計を同じ現行文書に残していた。

## 選択肢と比較

| 選択肢 | 利点 | 欠点・制約 | 採否 |
| :--- | :--- | :--- | :--- |
| 基本の登録・履歴・集計だけを今回の対象にする | 基本機能へ集中できる | 既存の周辺機能の整合は後回し | 不採用 |
| 既存の全9機能を対象にする | 全文書を同じ対象範囲で揃えられる | 文書・検証対象が広い | ownerが採用 |

## 決定と理由

ownerは2026-11-01の範囲確認に「既存資料の全9機能を対象にする」と回答した。ダッシュボード・手動支出・履歴・予算・カテゴリ・外部決済・クラウド同期・共通UI・アイコンを対象とする。追加時期や画面差だけで分けず、旧14識別子は9責務へ集約する。

業務要求はREQ、方式と画面はSPEC、検証計画・結果はVERIFYを正本とする。旧本文と図は過去資料として保持し、現行仕様と混在させない。実装との差分は改修対象として記録し、文書をコードの未完成状態へ合わせて要求を削らない。

## 要求・設計・検証への影響と反映状況

| 対象 | 正本・項目 | 影響 | 状況 |
| :--- | :--- | :--- | :--- |
| REQ | [一覧と9機能のAC](../req/REQ.md) | 全9機能の責務・範囲・基準を確定 | done |
| SPEC | [一覧・共通スキーマ・9設計](../spec/SPEC.md)、[画面](../spec/screens.drawio) | 旧資料の矛盾を解消して一本化 | done |
| VERIFY | [9計画とAC対応](../verification/VERIFY.md) | 全対象の正常・異常・境界・状態遷移を計画 | 計画done、結果は未実施 |

各インデックスから本ADRへ逆リンクする。ADRの採用は実装・検証の完了を意味せず、各レイヤーのdoneゲートを置き換えない。

## リスク・トレードオフ

対象拡大により現在のコードとの差分が増える。差分は[STATUS](../STATUS.md)へ明示し、確定計画に従って実装・検証する。旧文書の記述は履歴として保存し、現行設計の代替として使わない。

## 未解決事項

本ADRの対象範囲について未解決事項なし。アプリの実装追従・環境構築・検証実施は後続作業であり、文書確定や採用判断の未解決事項と混同しない。
