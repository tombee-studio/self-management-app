# ADR-0003: 端末DBを廃止しAWS APIへ読み書きを集約する

- **バージョン**: v2.0.0
- **ステータス**: done
- **更新日**: 2026-11-01（JST）

- **決定状態**: accepted
- **日付**: 2026-11-01（JST）
- **決定者**: owner（「ローカルDB自体を設計から削除し、AWS APIを通じた読み書きに変更する」と明示回答）

## 背景・課題・制約

従来設計は端末SQLiteとDynamoDBの二重保存、Push/Pull・Outbox・端末DB移行を前提とした。ownerがこの前提を廃止した。全9機能、業務の金額・検索・予算・カテゴリ・UIの範囲とAC識別子は維持し、保存方式・通信・競合の意味を明示的に改訂する。

## 選択肢と比較

| 選択肢 | 利点 | 制約 | 判断 |
| :--- | :--- | :--- | :--- |
| 端末DBを維持し設計制約だけ除去 | オフライン機能維持 | ownerの回答と異なる | 不採用 |
| AWS APIへ読み書きを集約 | 保存先・業務判定をサーバーへ集約 | 通信必須、API機能追加、読取費用 | owner指定として採用 |

## 決定と理由

端末DB・業務キャッシュ・保留送信・Push/Pull同期を設計から削除する。アプリはHTTPS API Gateway → Lambda → DynamoDBを使用する。DynamoDB直接アクセスはアプリへ許可しない。DDDの集約/Port/UnitOfWorkはLambda側に配置し、画面/入力/HTTP Adapterはアプリに配置する。

保存成功はAPI commit確定応答後。タイムアウトは結果不明として同じrequestIdで再送し、DynamoDBのReceiptで冪等化する。集約版CASとowner世代で競合/Query整合性を保証し、端末時計LWWは削除する。カテゴリ廃止はCatalogの恒久的な未分類対応とBudget配分削除を同取引で可視化し、大量明細の一括取引を不要にする。

HTTPは破壊的変更の版3、操作契約は版2。CategoryRetiredの配列から件数へのpayload変更により内部イベントも版2。端末DB版管理は削除する。

| 対象 | 正本 | 変更 |
| :--- | :--- | :--- |
| REQ | [一覧/ARCH-02](../req/REQ.md#arch-02-aws-api経由の読み書き)、クラウド/手動支出/決済 | オフライン保存・参照を対象外。クラウドAC-01〜07、手動AC-08、決済AC-03の意味を改訂 |

既存のクラウド機能へ責務を集約し、aws-cloud-database-syncの識別子/ファイル名を維持する。機能数を増やさない。

## リスク・トレードオフ

ネットワークなしでは新規取得/保存できない。セッション中の入力と直前表示だけを保持する。全件検索・集計のレイテンシーと費用は実環境で測定する。通知はサーバーreceipt後のOS通知試行で、端末が停止した場合の配信は保証しない。

既存端末DBの移送・自動アップロード・消去は今回対象外。既存クラウドの移行では書込停止・バックアップ・件数/総額比較を必須とする。認証方式追加は今回対象外で固定OwnerIdを認証としない。公開サービスとしての認証問題を解決済みと扱わない。

## 未解決事項・完了範囲

設計方式のowner判断待ちはなし。実装コードの変更・AWS apply・デプロイ・実機検証は本作業に含めない。現行実装は旧SQLite/同期方式のため未適合。文書レビューの合格を実装完了としない。
