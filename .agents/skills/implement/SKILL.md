# 支出機能実装スキル (implement-expense-feature)

本スキルは、支出管理アプリにおける新機能の開発や既存機能の拡張を、ドキュメント駆動かつ高品質に進めるための標準開発手順です。

- **バージョン**: v2.1.0
- **ステータス**: done

## 適用契機
- 支出の追加・編集・削除機能の実装
- カテゴリ管理や予算設定機能の実装
- 月次・週次の集計やグラフ可視化機能の実装
- データのローカル保存（SQLite/IndexedDB/localStorage）や外部連携の実装

## ワークフロー手順

### 1. 仕様・設計の事前確認
1. [運用](../../../docs/operations/OPERATIONS.md)と全運用文書、[REQ](../../../docs/req/REQ.md)、[SPEC](../../../docs/spec/SPEC.md)、[VERIFY](../../../docs/verification/VERIFY.md)と対象機能文書を確認する。
2. REQ・SPEC・VERIFY計画と各インデックスが全件doneになってから実装する。設計の振る舞い・データモデル・アーキテクチャはSPECを正本とする。
3. 要件や設計に未定義な部分がある場合、先にドキュメントを更新するかユーザーに確認を行う。

### 2. データモデル・ビジネスロジックの実装
1. 金額計算（小数点誤差の防止、通貨単位、合計計算）や日付処理のロジックを分離して実装する。
2. コアロジックに対する単体テストを作成し、境界値（0円、負の値、不正な日付など）の動作を検証する。

### 3. UI・コンポーネントの実装
1. 入力フォームのバリデーション（必須入力、数値制限など）を実装する。
2. レスポンシブで直感的なUIデザインを適用し、操作フィードバック（登録成功トースト、ローディングなど）を提供する。

### 4. ドキュメントの同期と完了確認
1. 矛盾・制約が見つかった場合は上位文書を先に修正・確定し、[ai-docs](../ai-docs/SKILL.md)のレビュー手順に従って下位へ同期する。削除済みのレガシー資料・互換案内を再作成しない。
2. 動作確認および静的解析（Lint/テスト）を実行して問題がないことを確認する。

確定計画に沿って検証し、結果・証跡をVERIFYへ記録する。全必須ケース合格と結果レビューdoneまで実装完了として扱わない。
